# 0.3.16 — tidier game folder (2026-10-01)

Player request: fewer files in the game folder and all logs in one place.

## What changes

- **Logs:** the 12 stage modules (Danger Zone, DNZ-*, Crimson, Crimson-Audio, Crimson-VFX, ExtraStages,
  RandomStages, DebugArchive) write to `<game>\DOA5LR-Logs\`. On first start each module moves its old log
  (and `.old`) from the game folder into it; a log bigger than 4 MB is deleted instead. If the folder cannot be
  created the log stays in the game folder. No other behaviour change: every module was rebuilt from the source of
  the shipped binary (verified byte-identical apart from the PE timestamp before the edit).
  ExtraStages 2.0.4 → 2.0.5, Crimson-VFX log header v26 → v27 (logging only). The `.ini` files do not move.
- **Stage modules folder:** the 11 stage `.asi` go to `scripts\DOA5LR-Stages\`. The pack's ASI loader also loads
  sub-folders of `scripts\` (verified with a probe module); modules find each other by file name, so nothing else
  changes. `DOA5LR-DebugArchive.asi` and `DOA5LR-ReplayTakeover.asi` stay next to `game.exe`.
- **Installer 1.3.11:** new component for the key `optional_v7` (older installers ignore it and keep reading
  `optional_v5`); required files point to the new folder; a maps module found both in `scripts\` and
  `scripts\DOA5LR-Stages\` is removed from `scripts\` (the same file name in two folders would be loaded twice).
- **DOA5LR-Diagnostic:** reads stage logs from `DOA5LR-Logs\` as well as the game folder.

Not changed in this step (online modules, need a two-player room retest): JoinFix, InputBridge, Lobby,
Replay Takeover and their logs.

## Manifest lines the 0.3.16 builder must write

1. `optional_v7=maps|<same label>|<globs of Component.Maps in Installer.cs, same order>` **before** the existing
   `optional_v5=maps|…` line (the first line with a given id wins; 1.3.5–1.3.10 ignore `optional_v7`).
2. `delete=scripts\DOA5LR-<name>.asi` for the 11 stage modules. **Mandatory:** installers 1.3.5–1.3.10 have no
   duplicate guard; with these lines they install the new layout cleanly (tested with the real 1.3.10).
3. `delete=DOA5LR-DNZ-Menu.log` and `delete=DOA5LR-DangerZone-crash.txt` (orphans of removed modules).
4. `installer_version=1.3.11` so installers offer their self-update first.

Known limit: an installer older than 1.3.11 run in `--auto` reports the four new required paths as missing only in
its own check (the files are there and the game loads them); a player who left the maps out still receives the
modules in the new folder (they refuse to start without the stage data).
